# 배너 영상 경량화 (2026-10-28)

로컬 구현·검증 기록이다. 사용자 요청에 따라 배포 소스를 Git에 정리하며, 공개 서버 실행 결과는 아직 확인 전이다.
앞서 배포된 `cf82ef7`의 첫 배너 표시 개선과 별개로, 재생 중 버퍼링을 줄이기 위한 변경이다.

## 배경·선택

- 공개 TWS 원본의 단일 다운로드 측정: 2,336,948bytes를 28.889초에 전송, 평균 약 0.65Mbps.
  17.1초 영상의 평균 필요량 약 1.09Mbps보다 낮았다. 이 측정만으로 ngrok·회선 중 병목을 특정하지 않는다.
- 원본 세 파일은 수정하지 않고 SHA256 일치를 확인했다.
- 540p 300kbps와 720p 380kbps 두 후보를 각각 만들었다. 두 후보 모두 오디오 AAC 64kbps,
  H264·24fps·2pass·faststart·2초 GOP를 사용했다. 기존 소리 버튼을 계속 사용할 수 있다.
- 같은 장면 비교 후 전송 여유를 우선해 540p 후보를 로컬 배너에 연결했다.
  화질은 원본과 동일하지 않다. 특히 빠른 춤 동작·배경의 세부 표현은 감소한다.
  720p 후보도 로컬 도구 폴더에 보존하며 공개 전달 경로가 개선되면 다시 비교할 수 있다.

| 영상 | 원본 bytes | 선택한 경량본 bytes | 감소 |
| --- | ---: | ---: | ---: |
| TWS | 2,336,948 | 790,587 | 66.2% |
| CORTIS | 4,965,966 | 841,742 | 83.0% |
| LE SSERAFIM | 2,463,396 | 868,523 | 64.7% |

새 파일명에는 해시를 붙여 기존 캐시와 구분한다. 파일 목록·원본/경량본 SHA256은
[자산 기록](P2_HERO_VIDEO_ASSETS.json)을 참조한다.
경량본은 총 평균 0.45Mbps 미만이며 원본과 재생 길이 차이가 0.1초 미만이다.
전송 속도의 변동·동시 접속·다른 리소스 경쟁이 있으므로 끊김 해소를 보장하는 수치가 아니다.

## 검증·재현

- 6개 후보 모두 FFmpeg 전체 디코딩 성공. 원본 세 파일의 SHA256 불변.
- 프론트 테스트 37개 통과: H264/AAC 보존·960×540·재생 길이·faststart·총 비트레이트·파일 해시 확인.
- 새 영상 경로의 정적 응답에서 Range 요청 206·1,024bytes 반환 확인.
- 브라우저에서 새 경량 영상 배너 재생 확인. 초기 음소거·소리 버튼 유지.
- lint·typecheck 및 Linux Next.js standalone 운영 이미지 빌드 통과.
- 배포 도구는 고정 원본 파일명이 아니라 묶음의 heroVideos.ts에 지정된 실제 첫 영상 URL을 검증하도록 보완했다.
- DB·API 업무 로직·Nginx 설정은 변경하지 않았다. 공개 서버에는 아직 적용하지 않았다.

```powershell
# 원본을 변경하지 않고 Git 제외 폴더에 540p/720p 후보 생성. ffmpeg는 별도 로컬 도구다.
python scripts/encode-hero-videos.py --ffmpeg '로컬 ffmpeg 실행 파일 경로'
npm test
node scripts/check-home-hero.mjs
node scripts/check-home-hero.mjs --fail-products
python deploy/staging/check_deploy_web.py
```

인코딩 도구는 프로젝트 런타임 의존성에 추가하지 않았다. 이번 검증에는 PyPI imageio-ffmpeg 0.6.0에
포함된 FFmpeg 7.1 실행 파일을 Git 제외 도구 폴더에서 사용했다.
서버 내부와 외부 전송 속도 비교·공개 네트워크 재생 확인은 후속 배포 시 수행해야 한다.
