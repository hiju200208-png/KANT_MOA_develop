# 상품 목록 초기 조회량 개선 (2026-10-28)

## 변경

기존 `productRange`는 화면에 20개를 표시할 때도 API에서 100개를 받고 80개를 버렸다.
화면의 요청 수가 100개 이하면 그 수를 페이지 크기로 사용하고, 그 이상은 기존처럼 최대
100개씩 나눠 읽는다. 상품 목록·검색·홈 상품 선정에서 같은 변환 함수를 재사용한다.

정렬·총 개수·더 보기·offset 결과와 조회 실패 처리는 유지한다. 상품 데이터 캐시를 추가하지
않으므로 관리자 변경과 재고·판매 상태의 최신 조회 기준도 유지한다.

## 측정과 검증

- 배포 전 공개 API를 읽기 전용으로 조회한 단일 표본: size=100은 100개·41,303bytes·1.957초,
  size=20은 20개·8,565bytes·0.869초였다. 순차 요청이며 시점이 달라 통제된 속도 비교는 아니다.
- 별도 상품 페이지 HTML 전체 수신은 2.560초였다. 이미지 다운로드를 제외한 값이므로
  사진 수만으로 대기 시간을 설명할 수 없다.
- 대표 이미지 하나는 32,720bytes·0.606초였다. 전체 이미지의 평균이나 최대 크기를 뜻하지 않는다.
- lint·typecheck·프론트 테스트 37개 통과. 페이지 경계를 걸치는 offset, 마지막 페이지,
  최대 500개, 빈 결과 및 오류 전달을 검증했다.
- 실제 공개 API 주소를 빌드 인자로 사용한 Linux 운영 이미지 빌드 통과.

공용 DB·마이그레이션·시드·이미지 원본은 변경하지 않는다. 배포는 홈페이지 서비스만 교체한다.
공개 배포 후 체감 시간과 이미지 대기는 별도로 확인한다.
