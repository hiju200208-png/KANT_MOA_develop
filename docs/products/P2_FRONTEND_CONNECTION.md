## 구현 범위

- 상품 목록·카테고리·검색·상세: FastAPI 공개 API 사용. 요청 실패 시 예비 상품으로 대체하지 않는다.
- `catalogMapping.ts`: snake_case → camelCase, 이미지 URL, page/size → limit/offset 변환.
  API 한 페이지 최대 100개에 맞춰 기존 화면의 최대 500개 조회와 중간 offset을 처리한다.
- 공개 조회와 개인 찜 모두 `no-store`. 공개 조회에는 회원 토큰·쿠키를 전달하지 않는다.
  판매 상태는 다음 서버 조회/새로고침에 반영한다. 열린 화면 실시간 push는 구현하지 않았다.
- 찜 목록/IDs/PUT/DELETE 연결. 최초 상태 확인 전 쓰기 차단, 연타 차단, 실패 원복,
  오류 표시·재시도, 계정 변경 중 이전 응답 무시를 적용했다.
- 사용자 승인으로 P1 이메일 회원가입·로그인·내 정보·블랙리스트 로그아웃 API를 최소 연결했다.
  P3·P4와 동일한 `kantmoa.accessToken` 키를 사용한다. 새로고침·탭 간 변경·focus 시 회원 상태를 조회한다.
  인증된 요청의 401은 해당 요청 토큰이 현재 토큰과 같을 때만 삭제한다.
  로그아웃 통신 실패는 화면에 표시하고 성공한 것처럼 토큰을 삭제하지 않는다.

## 로컬 설정과 공통 파일

`.env.local`에 `NEXT_PUBLIC_API_URL=http://localhost:8000`을 지정한다.
선택적으로 `API_INTERNAL_URL=http://127.0.0.1:8000`을 지정하면 서버 컴포넌트만 내부 주소를 쓴다.
브라우저용 주소는 이미지에도 쓰이며 빌드 시 고정되므로 변경 후 다시 빌드한다.
API의 `CORS_ORIGINS`에는 실제 프론트 origin을 정확히 등록한다. localhost와 127.0.0.1은 서로 다른 origin이다.

ngrok 브라우저 API 호출의 안내 페이지를 피하기 위한 헤더를 추가하고,
backend `main.py` CORS 허용 헤더에 `ngrok-skip-browser-warning`을 추가했다.
`next.config.ts`는 API `/static`, `/uploads` 이미지 주소를 등록한다.
이미 압축된 API 이미지는 개별 컴포넌트에서 `unoptimized`로 표시한다.
Supabase 설정 없는 상품 화면도 열리도록 기존 공개 클라이언트를 지연 초기화했다.
공통 인증·API·설정 변경은 PR 전 P1에게 공유할 대상이다. 아직 메시지를 전송하지 않았다.
Next.js와 eslint-config-next는 `16.4.0` → `16.4.3`으로 패치하고 package-lock도 동기화했다.
홈·아티스트 목록·Footer의 기존 외부 데이터 영역은 `io()` 후 요청 시 렌더한다.
빌드 시 기존 Supabase 데이터 조회가 실패해 전체 빌드가 중단되는 것을 막으며 기존 오류 표시를 유지한다.
